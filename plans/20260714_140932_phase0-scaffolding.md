## 1. What the issue is

There is no Flutter project yet — only the `doc/`, `plans/`, and `change_log/` folders. Nothing
can be built, run, or tested until the project skeleton, the app start-up sequence, and the
shared services (config, logging, errors, database, theme, routing, localization) exist.

Phase 0 is "done" when the app launches to an empty **Home** screen with working **About** and
**Settings** screens, and `flutter analyze`, `flutter test`, and `dart format` are all clean.

Two things are not fixed by the docs. I propose defaults below; please confirm or change them

2. **Java toolchain (build-time risk).** The machine has **Java 24** installed, but the guideline

   validated newer JDKs. Plan: point Flutter's Android build at a **JDK 17** using

   I will flag it and we install one (for example Temurin 17) before the first Android build.
   The Dart-only work (analyze, test, format) does not need this and can proceed regardless.

## 4. Files to be created or changed

### 4.1 Generated by `flutter create`, then adjusted
- `android/app/build.gradle.kts` — set application id, `minSdk 26`, Java 17, `dev`/`prod` product
  flavors (§5.3 of the standard), keep AGP 8.x (do **not** move to AGP 9).
- `android/app/src/main/AndroidManifest.xml` — app label from flavor; **no `INTERNET`
  permission**; `android:debuggable` left to the build type (release = false).
- `android/build.gradle.kts`, `settings.gradle.kts`, `gradle.properties` — as generated; only
  touched if flavors/JDK need it.
- `pubspec.yaml`, `analysis_options.yaml`, `.gitignore`, `.metadata` — regenerated/edited.

### 4.2 Config, constants, flavor (fixed About pattern — `guideline.md §1`)
- `assets/config/app_config.json` — About values (appName, description, version, build, details).
- `lib/core/config/app_config.dart` — `AppConfig` model (`fromJson` + `fallback`), exactly as
  the guideline reference.
- `lib/core/config/config_service.dart` — `ConfigService` (`load()` + `loadAndVerify()`).
- `lib/core/constants/app_constants.dart` — `AppConstants` (db name, table names, method-channel
  ids, size thresholds — values only, no logic).
- `lib/app/config/app_flavor_config.dart` — `AppFlavor` enum + `AppFlavorConfig` (two-variable
  pattern from standard §5.2).

### 4.3 Cross-cutting core services
- `lib/core/logging/app_logger.dart` — `AppLogger` with the level taxonomy (standard §14).
- `lib/core/errors/app_exception.dart` — sealed `AppException` hierarchy
  (`StorageException`, `ValidationException`, plus a `PdfException` base for later phases).
- `lib/core/errors/safe_error_fallback.dart` — `SafeErrorFallback` widget (release error box).
- `lib/core/lifecycle/app_lifecycle_service.dart` — `AppLifecycleService`
  (`WidgetsBindingObserver`).
- `lib/core/storage/app_database.dart` — sqflite bootstrap: WAL on, FKs on (`onConfigure`),
  versioned migration runner, **schema v1 = a `meta` base table** (baseline; feature tables come
  in later phases).
- `lib/core/storage/migrations.dart` — the `Map<int, migration>` table, v1 only for now.

### 4.4 App shell: theme, routing, localization, root
- `lib/app/theme/tokens.dart` — design tokens (colors, spacing, radius, motion) — single source.
- `lib/app/theme/app_theme.dart` — Material 3 light, dark, and sepia `ThemeData` from tokens.
- `lib/app/routing/app_router.dart` — go_router with placeholder routes: Home, Viewer, Settings,
  About (centralized, standard §6.9).
- `lib/app/app.dart` — root `MaterialApp.router` (theme + localization delegates + router).
- `lib/l10n/app_en.arb`, `lib/l10n/app_ml.arb` — English + Malayalam strings (start small:
  app title, Home/Settings/About labels, a few shared strings).
- `l10n.yaml` — generator config (standard §8.1; `synthetic-package: false`).
- `lib/main.dart` — thin `main()` init sequence (standard §4.5 / §11.1):
  binding → db open+migrate → config load → `AppLogger.init` → lifecycle observer →
  global error handlers (`FlutterError.onError`, `PlatformDispatcher.instance.onError`,
  release `ErrorWidget.builder` → `SafeErrorFallback`) → `runApp(ProviderScope(...))`.

### 4.5 Placeholder feature screens (Tier 2 `features/`)

## 6. Key rules this phase must honor

- **About pattern fixed** — exact paths/class names (`guideline.md §1`).
- **Offline** — no `INTERNET` permission in the manifest.
- **Never crash** — every init step has a failure path; release shows `SafeErrorFallback`.
- **One state pattern** — Riverpod only.
- **`const` everywhere it compiles; `ListView.builder` for unbounded lists; `AppLogger` only** —
  no `print`/`debugPrint` (standard §22.2).
- **Keystore rules** — `.gitignore` excludes `android/key.properties`, `android/*.jks`,
  `android/*.keystore` (`guideline.md §2.3`). (No keystore is created in Phase 0; that is Phase 8.)
