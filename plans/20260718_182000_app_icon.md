# App Launcher Icon

**Status:** completed

## What the issue is

The app still ships the **default Flutter launcher icon** (the plain white
square). There is no branded icon and no adaptive icon. `minSdk` is 26, so
every device supports (and prefers) **adaptive icons**, but none are set up.

## The design (agreed with user)

- **Concept:** a PDF document sheet combined with a small printer at the
  bottom — nods to both "read PDFs" and "print to PDF".
- **Color:** match the app theme. The Material seed is `#3D5A80`
  (slate blue, `lib/app/theme/tokens.dart`). The tile uses a slate‑blue
  gradient; the document + printer are white.
- **Adaptive icon:**
  - **Background layer** = slate‑blue gradient (top `#4A6A94` → bottom `#2E4460`).
  - **Foreground layer** = white document (folded top‑right corner, a couple
    of text lines) sitting on a white printer body, drawn inside the adaptive
    **safe zone** (centered, kept within the inner ~66 of 108 units so no
    launcher mask clips it).
- **Legacy icon** (`ic_launcher.png`) = the same art composed on a rounded
  slate tile, for older/Play contexts.

## How I will build it (fully offline)

No ImageMagick/Inkscape is available, but Windows PowerShell + .NET
`System.Drawing` can render PNGs (gradients, shapes, anti‑aliasing). I will
write one generator script that draws the art vectorally and exports every
density. Keeping the script in the repo means the icon can be regenerated or
tweaked later.

Densities:
- Legacy `ic_launcher.png`: 48 / 72 / 96 / 144 / 192 px
  (mdpi/hdpi/xhdpi/xxhdpi/xxxhdpi).
- Adaptive foreground & background (108dp): 108 / 162 / 216 / 324 / 432 px.
- One 1024px master PNG for the Play Store listing.

## Files to be changed

**New**
- `tool/generate_icon.ps1` — the icon generator (kept for future edits).
- `android/app/src/main/res/mipmap-anydpi-v26/ic_launcher.xml` — adaptive icon.
- `android/app/src/main/res/mipmap-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}/ic_launcher_foreground.png`
- `android/app/src/main/res/mipmap-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}/ic_launcher_background.png`
- `assets/branding/ic_launcher_1024.png` — store master (not bundled in app).

**Modified**
- `android/app/src/main/res/mipmap-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}/ic_launcher.png`
  — replaced with the new branded art.

No change to `AndroidManifest.xml` is needed: it already points at
`@mipmap/ic_launcher`, and the new `mipmap-anydpi-v26/ic_launcher.xml` makes
Android use the adaptive version automatically on all supported devices.

## Steps

1. Write `tool/generate_icon.ps1`.
2. Run it to produce all PNGs into the res folders + the 1024 master.
3. Add `mipmap-anydpi-v26/ic_launcher.xml`.
4. Build a debug APK (or at least `flutter build apk --debug` up to resource
   merge) to confirm resources compile, and eyeball the master PNG.
5. Write the change log.

## Verification

- Confirm all expected PNGs exist at the right sizes.
- Open the 1024 master to visually check the design.
- `flutter build apk --debug` succeeds (icon resources merge cleanly).

## Notes / risks

- `System.Drawing.Common` on Windows PowerShell is fine for this; if a call
  is unavailable I fall back to drawing primitives only (no external fonts —
  the "PDF" hint lines are drawn as rectangles, not real text, so no font
  dependency).
- Copy‑on‑write / storage rules are unaffected (this only touches build
  resources).
