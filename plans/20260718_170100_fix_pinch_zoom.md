# Plan - Fix Pinch-Zoom Issue After Menu Actions

**Status:** completed

## Problem Description

When clicking on certain menu items (such as "Invert Colors", changing "View Mode", opening search, or toggling annotation mode), pinch-to-zoom stops working. 

### Root Cause
1. **Tree Restructuring & Shifted Indices:** When menu items are clicked, they update flags in `ViewerScreen` (e.g., `_invert`, `_annotateMode`, `_showNotice`, `_showAnnotationNotice`). These flags conditionally insert/remove elements at the beginning of the body `Column`. In Flutter, this shifts the index of the `Expanded(child: ...)` widget containing the PDF viewer subtree. 
2. **Parent Widget Depth Change:** Toggling `_invert` wraps the subtree in a `ColorFiltered` widget or removes it, changing the path/depth of `PinchZoomWrapper` in the element tree.
3. **Element Destruction & Controller Detachment:** Without a `GlobalKey`, Flutter cannot match the old elements to the new ones after these shifts. Thus, the old `PinchZoomWrapper` and `PdfViewer` elements are destroyed and recreated. Due to Flutter's lifecycle timing, the new `PdfViewerState` initializes and attaches to the controller, and then immediately after, the old `PdfViewerState` is disposed and detaches from the controller. This leaves the `PdfViewerController` permanently detached (`isReady: false`).

---

## Proposed Changes

We will fix this by:
1. **Preserving the Subtree State with a `GlobalKey`:** Adding a stable `GlobalKey` to the `PinchZoomWrapper` so that Flutter's reconciler reparents/moves the element subtree instead of disposing and recreating it.
2. **Stabilizing the ColorFiltered Depth:** Always rendering the `ColorFiltered` widget in `_buildBody` but passing an identity matrix filter (which does nothing) when `_invert` is false, ensuring the widget depth never changes.
