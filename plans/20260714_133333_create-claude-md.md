# Plan — Create a minimal CLAUDE.md with split subfiles

**Status:** completed

## What is the issue / goal

The PDF app has no `CLAUDE.md` yet. The sibling project `SreerajP_TextApp` already has a proven
pattern — a short `CLAUDE.md` at the root that points to detail files under `docs/`. This plan
copies that pattern for the PDF app, using the PDF app's existing `doc/` folder.

Sources:
- `doc/GUIDELINES_MANIFEST.md` — pointer to the shared Flutter guidelines (master source of truth).
- `doc/PDF-Idea.md` — the full product idea (what the app is, features, risks, library choice, NFRs).
- Pattern reference: `L:\Android\SreerajP_TextApp\CLAUDE.md` + `docs/workflow-rules.md` +
  `docs/security-rules.md`.

The user wants: a `CLAUDE.md` that is **minimal**, with detail **split into subfiles in `doc/`**,
and it must include the **global workflow rules** about the `plans/` file and the `change_log/` file.

## Plan for the content

### `CLAUDE.md` (minimal — same section layout as TextApp)
1. **What this app is** — one line + pointer to `doc/PDF-Idea.md`.
2. **Tech stack (fixed)** — Flutter 3.41.9+, Dart 3.11.5+, minSdk 26, Material 3.
3. **Hard rules for this project** — must-follow rules:
   - Open source only (no Syncfusion / PSPDFKit / Apryse).
   - Offline-first (only optional online part is opening remote links).
   - Scoped storage only (SAF picker + "Open with" intents; no broad permission, no file browser).
   - Never crash on bad input (corrupt / truncated / empty / password-protected → friendly message).
   - Copy-on-write — every page operation writes a new file; the original is never modified in place.
   - Never a dead button — shared modules (esp. Malayalam TTS) report ready / needs-install /
     unavailable state; reader screens never show a silently broken control.
   - OCR is out of scope; scanned (no-text-layer) PDFs degrade gracefully with a notice.
4. **Guidelines** — follow `doc/GUIDELINES_MANIFEST.md`; a local `doc/` copy wins over the master.
5. **Security rules** — pointer to `doc/security-rules.md`; read it before touching security code.
6. **Where things live** — short tree (CLAUDE.md, doc/, plans/, change_log/, lib/ later).
7. **Workflow rules (mandatory)** — pointer to `doc/workflow-rules.md`; plan+approval before,
   change log after.
8. **Communication rules** — always simple English.

### `doc/workflow-rules.md`
Same content as TextApp's: plan-before-changing (naming, required sections, Status values and
lifecycle), the approval gate, and log-after-changing. Adapted to reference `../CLAUDE.md`.

### `doc/security-rules.md`
PDF-specific security rules drawn from `PDF-Idea.md`'s Non-Functional Requirements and Risks:
- Treat every opened PDF as untrusted input; never send file contents anywhere without an
  explicit user action (share/export).
- Signature verification is done **locally** (PKCS#7/CMS via native Bouncy Castle +
  `CertPathValidator`); "globally trusted" = bundled AATL/EUTL lists, not the Android TLS CA store.
- Copy-on-write for all page operations; original write access is not required.
- Passwords / secrets are never logged; encrypt/decrypt handled carefully.
- File identity keyed to a content fingerprint (size + hash); a modified file is a new document.
- Never crash on malformed input; every parser has a failure path.
