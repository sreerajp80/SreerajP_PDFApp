# App Launcher Icon v2 — Reader/Editor + Printer

**Status:** completed

## What the issue is

The current icon (`plans/20260718_182000_app_icon.md`) shows a document
emerging from a printer. At small sizes it reads only as a **PDF printer**, not
as a **PDF reader/editor**. The user wants the icon to say all three:
**read, edit, print.**

## The design (agreed with user)

Composition: **PDF page + pen, small printer** — the document is the hero.

- **Hero: PDF document sheet** (reader). A large white sheet with a dog-eared
  top-right corner, a couple of content lines, and a bold **"PDF"** label.
  Bigger and higher than before so it dominates and stays legible small.
- **Pen/pencil across the sheet** (editor). A pen laid diagonally over the lower
  part of the sheet, in a warm accent (amber `#E6A94B`, the color already used
  for the printer LED), so "edit" reads at a glance.
- **Small printer at the bottom** (printer). Shrunk and pushed to the base so it
  supports the story without stealing focus. The sheet overlaps its top so it
  still says "print".
- **Tile / colors unchanged:** slate-blue gradient tile matching the app theme
  seed `#3D5A80`; document white; slate content lines.

## How I will build it

Reuse the existing generator `tool/generate_icon.ps1` (PowerShell + .NET
`System.Drawing`, fully offline). I will rework the `Draw-Art` function:
- enlarge + raise the sheet so it is the clear hero,
- shrink the printer and move it down,
- add a pen drawn as a rounded body + nib (amber) across the sheet,
- re-balance the content lines / "PDF" label for the new sheet size.

Then re-run the script to regenerate every asset. Same output files and sizes as
before, so nothing else needs to change.

## Steps

2. Run the script; regenerate all PNGs + the 1024 master.
3. Visually check the 1024 master and a small (48px) render for legibility, and
   a composited adaptive preview against the circular mask.
4. Iterate on the layout if the small size looks cluttered.
5. Write the change log.

## Verification

- Open the 1024 master and a 48px render — the page + pen must read clearly, the
  printer must not dominate.
- Composited foreground+background stays inside the adaptive safe zone.
- All expected PNGs regenerated at the right sizes.

## Notes / risks

- Three elements risk clutter at 48px. Mitigation: printer is small and low,
  pen is a single bold diagonal, sheet is the hero. If 48px still looks busy I
  will simplify (e.g. thin the printer to a suggestion) before finishing.
