# SreerajP PDF App

An **offline Android app**, built in Flutter, for **everything PDF**: opening, reading,
searching, listening (English + Malayalam TTS), annotating, extracting, reorganizing, printing,
and verifying digital signatures. Only **open-source** libraries are used.

See [CLAUDE.md](CLAUDE.md) for the project rules and [docs/](docs/) for the product idea, full
technical design, and the phased implementation plan. Engineering-side design notes live in
[docs/architecture.md](docs/architecture.md).

## Prerequisites

- **Flutter 3.41.9+** and **Dart 3.11.5+** (`flutter --version`).
- **JDK 17** for the Android/Gradle build. Point Flutter at it if your default JDK differs:
  `flutter config --jdk-dir <path-to-jdk-17>` (or set `JAVA_HOME`).
- Android SDK with **minSdk 26** (Android 8.0). AGP 8.x — do **not** upgrade to AGP 9.

## Setup (clean clone to running app)

```bash
flutter pub get
flutter gen-l10n          # generate localization accessors (also runs on build)
flutter run --flavor dev  # dev flavor -> app id in.sreerajp.pdfapp.dev
```

## Flavors

- `dev` — application id `in.sreerajp.pdfapp.dev`, label "PDF App Dev".
- `prod` — application id `in.sreerajp.pdfapp`, label "PDF App".

Android/iOS use `--flavor`; the Flutter tool injects `FLUTTER_APP_FLAVOR`. (There are no desktop
targets, so the `APP_FLAVOR` dart-define path is not used here.)

```bash
flutter run --flavor dev
flutter build apk --flavor prod --release
```

## Tests

```bash
flutter test
```

Database tests run on the host via `sqflite_common_ffi`. `test/` mirrors `lib/`.

## Code generation

Localizations are generated by `flutter gen-l10n` (config in `l10n.yaml`, ARB files in
`lib/l10n/`). No `build_runner` code generation is used yet.

## Adding a database migration

Schema version and migrations live in `lib/core/storage/`:

1. Bump `AppConstants.databaseVersion` in `lib/core/constants/app_constants.dart`.
2. Add the new version's migration function to the `migrations` map in
   `lib/core/storage/migrations.dart` (append-only — never edit a shipped migration).
3. Add an upgrade-path test in `test/core/storage/` covering v1 → current.
4. Record the new version in [docs/architecture.md](docs/architecture.md).
